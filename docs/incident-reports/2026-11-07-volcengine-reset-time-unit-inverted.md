## 0. 结论摘要

| 维度 | 结论 |
|------|------|
| 性质 | **时间戳单位判断条件写反**，把服务端毫秒当成秒用 |
| 现象 | 5h 配额用光后，状态栏括号显示 `497849573h53m`；Popup 显示「重置于 6,712年11个月」 |

| 附带 | 加纵深防御：算出「远在未来（>60 天）」的病态日期 → 退回「N 小时后重置」 |

## 1. 现象（用户实测）

用户在火山方舟 5 小时配额用光后看到：

> 右上角状态栏里火山的字母 V 旁边，括号里显示 **497849573 小时 53 分钟**；
> 点开下拉菜单则写着 **「重置于 6,712年11个月」**。

两个数字看起来对不上（497849573 小时 ≈ 56854 年 vs 6712 年），
但它们是**同一个错误日期的两种渲染**：

- 状态栏：`MenuBarTitlePlan.compactDuration(remain)` 纯算术，秒 ÷ 3600 → 小时
- Popup：`Text(resetAt, style: .relative)` 交给系统，日历算法在公元 5 万多年这种越界年份上溢出环绕 → 「6,712年11个月」

（同一日期交给 Foundation 的 `RelativeDateTimeFormatter` 则是「56,794年后」——三套格式化器三种说法，
所以别被数值差异带偏方向。）

---

## 2. 根因

### 2.1 单位判断写反

```swift
// 修复前（VolcengineProvider.extractResetTime）
let seconds = ms < 1_000_000_000_000 ? ms / 1000 : ms
```

真实值 `1794052512000`（13 位）走 `else` 分支 → `seconds = 1794052512000` →
`Date(timeIntervalSince1970:)` 把它当秒 → 落到公元 58872 年。

**两个分支其实都错**：10 位的秒级时间戳会被 `/1000` 掉进 1970 年。
而注释写的又是「秒级（< 1e12）自动**乘** 1000」——注释与代码本身就自相矛盾，
说明写的时候概念就没对齐（`Date(timeIntervalSince1970:)` 收的是**秒**）。

### 2.2 为什么火山两个接口单位还不一样

| 接口 | 字段 | 单位 |
|---|---|---|
| `GetAFPUsage`（Agent Plan） | `ResetTime` | **毫秒**（13 位，实测 `1794052512000`） |
| `GetCodingPlanUsage`（降级路径） | `ResetTimestamp` | **秒**（官方示例 `1782057600`） |

所以自适应判断是必要的，只是方向写反了。
对照同代码库的 `MiniMaxProvider.epochMillis`（`ms > 1e12 ? ms/1000 : ms`）——**那才是对的**。

---

## 3. 修复

```swift
let seconds = v >= 1_000_000_000_000 ? v / 1000 : v
```

另加纵深防御（`plausibleResetDate`）：换算结果若**远在未来（>60 天）**视为单位又错了，
返回 nil 由调用方 fallback「N 小时后重置」，杜绝再次出现「几万年 / 6,712 年」这类 UI 事故。

顺带修掉一个同类问题：数字字符串形式的时间戳（`"1778806800000"`）此前会被 ISO8601
解析分支短路 → 静默 fallback 5 小时；现在按数字正确换算。

## 4. 为什么测试没拦住（这才是重点）

原测试是：

```swift
XCTAssertNotNil(quota.primaryWindow?.resetAt)
```

**公元 5 万多年同样满足「非 nil」** → 断言照常通过 → bug 从 v1.2.0 一路活到线上。

已改为双重断言：

```swift
XCTAssertEqual(resetAt.timeIntervalSince1970, 1_778_806_800, accuracy: 1.0)  // 精确时刻
XCTAssertLessThan(resetAt.timeIntervalSinceNow, 30 * 24 * 3600)               // 距今范围
```

**「非 nil」断言挡不住任何单位/数量级错误。凡是解析类字段，断言就该卡具体值。**
（后续千帆那轮又踩到同类问题：「取到非 nil 就当成功」——见
`2026-11-12-webkit-webview-app-modal-freeze.md`。）
