## 一、新增：百度千帆 Token Plan 配额监控

千帆的套餐余量没有开放的查询接口（我们把官方 424 个 API 文档页、数据面候选路径、
控制面 Action、以及社区参照实现都翻了一遍，确认没有），所以只能像 Google Gemini 那样
**登录控制台网页抓取**。本版把这套东西在千帆上跑通了。

### 你怎么用

1. 右键状态栏图标 → **设置…**
2. 「平台配置」区找到 **百度千帆** 行 → 点「**登录**」
3. 弹出的窗口里完成百度账号登录
4. 登录成功后窗口会自动关闭，该行显示绿色「已登录」

### 它给你看什么

| 状态栏 | 含义 |
|--------|------|
| `B 5` | 千帆 Token Plan 本月已用 5%（绿/黄/橙/红随阈值） |

点开 Popup 面板还能看到：

- **余量**：本月套餐已用百分比（例：已用 4.93%）
- **剩余 Token**：剩余数 / 总量（例：`665,463,337 / 700,000,000 Token`）
- **重置倒计时**：下次月重置时刻（例：`重置于 2026-12-11 14:51:08`）

### 使用须知

- 千帆是**包月总量制**（不是别家的 5 小时滚动窗口），所以它的重置是按月对齐的
- 登录态存在**本机**（只存 cookie，不存账号密码，不上传任何内容）
- 抓取频率上限 **5 分钟/次**（渲染整个控制台页，不高频访问百度）
- **登录一次就不用再登了**——本版起 cookie 会落盘，App 重启也不会掉登录态
- 登录过期时状态栏 `B` 显示 `!`，到设置里重新登录即可

## 二、修复：火山方舟倒计时显示「497849573 小时」

### 现象

> 火山方舟 5 小时配额用光后，状态栏括号里显示 **497849573 小时 53 分**，
> Popup 里写着「重置于 6,712年11个月」。

### 根因

服务端的重置时间戳是**毫秒**（13 位，如 `1794052512000`），代码按**秒**直接用了，
换算后落到公元 5 万多年。反过来，10 位的秒级时间戳又会被当成毫秒除以 1000，掉到 1970 年。

火山两个接口的单位本来就不一致（`GetAFPUsage` 用毫秒、`GetCodingPlanUsage` 用秒），
自适应判断的**条件写反了**，两个分支正好都错。

### 修完

时间戳单位判断改正为「13 位=毫秒、10 位=秒」，并加了一条兜底：
万一单位再变导致算出「几万年」这种病态日期，直接退回「N 小时后重置」，不再显示离谱数字。

## 三、稳定性加固：三个曾经会把 App 弄停的问题

这轮为了让千帆跑通，挖出并修掉了三个**互相独立**的老毛病，
它们此前一直存在，只是平时不容易撞上：

1. **登录窗口关闭时 App 会闪退**
   关闭窗口时延迟释放了一个系统可能已经释放过的窗口对象 → 主线程崩溃。
   现在窗口不再释放，而是复用（同一个窗口 + 同一个 WebView，cookie 不受影响）。

2. **弹出的钥匙串授权框点不动，而且会把整个 App 冻住**
   网页里的密码输入框会让浏览器引擎去访问系统钥匙串，弹出的授权框是「应用模态」的——
   一旦弹出，App 就进入模态会话，主线程被挂起，**连刷新都排不上队**，
   表现就是「App 开着但一个平台都不更新」。
   现在抓取用的网页会先屏蔽密码输入框，授权框根本不会出现。

3. **通知权限请求挡在首次刷新前面**
   系统通知授权在用户没点「允许/拒绝」时会一直挂着，把首次刷新一起拖住了。
   现在权限请求与刷新互不阻塞。

此外，本版还修好了**非沙盒 App 的浏览器引擎不落盘 cookie** 的问题：
以前每次重启 App 都要重新登录一遍千帆和 Gemini，现在登录态会持久化。

## 四、技术选型记录（给将来的人看）

- **千帆为什么只能走网页**：穷尽排查过——官方 API 文档全部 424 个页面里只有「查询免费实例额度」（那是向量数据库的）和「服务调用明细导出」（要导 CSV）；数据面 7 个 `/limits` 类路径全部 404；控制面 95 组 Action×Service 盲探全部 404；社区参照实现 CC Switch 的 Token Plan 模板（Kimi/GLM/MiniMax/火山/OpenCode/Command Code）也不含千帆。用户提供的 `bce-v3/AK/SK` 签名有效，但**只能调模型、查不到套餐余量**。
- **千帆控制台用的是同源 REST 接口**（`/api/qianfan/charge/user/info` 等），
  但套餐余量不在这批 XHR 里（实测 hook 全量扫描未命中，可能在微前端 iframe 内），
  故保留 WebView 抓取方案。
- **屏幕外窗口不会被渲染**：macOS 不合成屏幕外的窗口，浏览器引擎因此不渲染单页应用，
  页面正文只剩骨架（实测 165 字符 vs 屏幕内 1541 字符）。
  抓取窗口改为「完整尺寸 + 位置挪到屏幕右缘外」，用户看不见但确实在屏幕内。
- **非沙盒 App 的浏览器引擎不持久化 cookie**，需自行导出/恢复。
